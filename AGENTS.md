## Data contract

The enforced source-data spec is `scripts/validate_data.py`, supported by
`schemas/translatechan-data.schema.json`, `scripts/source_review.py`, and
`scripts/w1_evidence.py`. It protects:

- corpus/manifest agreement and known content shapes;
- translation status, provenance, and rights-manifest resolution;
- canonical locators and editorial queues;
- explicit W1 source-review statuses derived from dated evidence;
- completion compatibility: `complete_selected_witness` requires
  `collated_to_claimed_witness` and satisfied unit targets;
- deterministic `data/project_metrics.json`;
- current prose-doc truthfulness for measured data claims.

The data contract keeps **five separate ledgers**: Source collation (W1) · Represented units · Translation & edition verification · Canonical source locator · Rights review. These are semantic categories, not a prescribed HTML layout. Containment/remediation state, not a rights decision. Source collation does not approve reuse.

## Quality gates

Run before pushing:

```bash
python3 -m py_compile scripts/*.py
python3 scripts/validate_data.py
python3 scripts/build_pages.py
python3 scripts/test_source_preservation.py
python3 scripts/test_source_review_rules.py
python3 scripts/test_pages_contract.py
diff -rq data docs/data
git diff --check
```

`--write-metrics` is only for legitimate source-data changes and must fail closed
on blocking errors. The retired `smoke_test.mjs`, `compat_runtime_check.mjs`, and
`browser_test.mjs` are deleted; do not restore them as gates.

## Honest disclosure

Most English renderings are disclosed AI/register reconstructions, not citable
scholar wording. Verified quotations require recorded edition/source evidence and
remain separate from rights review. Never generate source-looking Classical Chinese;
re-key only from pinned, digest-verified witnesses. Never infer rights approval from
collation, representation counts, or edition verification.
