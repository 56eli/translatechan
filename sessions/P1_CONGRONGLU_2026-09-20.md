## 5. Why the candidate cannot land yet — three blockers, each with its verbatim evidence

Staging the candidate for real (corpus file + manifest item + locators + `DOCS` mapping) and running
the validator produces **17 errors**: three are the evidence wall, fourteen are the
documentation/metrics cascade that a 36-document landing must sweep.

**(1) A manifest item needs an evidence record in a pinned register — and there is no slot.**

```
❌ sessions/COLLATION_REGISTER_2026-09-10_CORRECTION.json.aggregate: harness documents without an evidence entry: congronglu
❌ data/corpus_manifest.json.source_review.items[congronglu]: declares source_review_status='collated_to_claimed_witness' with no evidence record in either W1 register — a status may not rest on the absence of a register entry
❌ data/corpus_manifest.json: manifest declares 2 item(s) with source_review_status='collated_to_claimed_witness' but the merged evidence derives 1; recompute the statuses from the registers
```

`FIXED_METADATA` pins exactly one historical register (2026-09-09, 34 documents) plus one
`w1-correction` overlay (2026-09-10, 35 documents); `validate_authoritative_register` requires
`harness_docs ⊆ register docs` and `documents_without_evidence == []`. The natural home for a new
document is the authoritative overlay — which is a dated evidence file whose own report must state
figures the register recomputes (`each of the N current manifest items`, the flagged totals, the
reconciliation table, the status counts), so the register and its report have to be amended
together. That is exactly what `RESEARCH_RELEASE_PLAN.md` (release-blocking checklist item 1,
2026-09-12 ruling) and `ROADMAP.md:174/188` reserve for an **owner-ruled change to the evidence
model** ("the pair cannot move without a deliberate, owner-ruled change"; "no
`scripts/w1_evidence.py` or `FIXED_METADATA` change").

**(2) The overlay check is single-document by construction.** `scripts/w1_evidence.py:1193-1212`
iterates the overlay-only documents and compares *the same* first prose matches against each
document's figures:

```python
overlay_only = sorted(set(auth_docs) - set(historical_docs))
for key in overlay_only:
    …
    fields_match = re.search(r"Content fields: (\d+) measured, (\d+) collated", prose)
    if fields_match and (int(fields_match.group(1)), int(fields_match.group(2))) != (
        entry["content_fields_total"], entry["content_fields_collated"]
    ):
        problems.error(…)
```

With two overlay documents (`shitou_sandokai`, 11/6) and a 500/500 candidate, one prose match
cannot satisfy both loops: extending the overlay to two documents requires changing this
single-document check — a gate-touching edit the 2026-09-12 ruling forbids without the owner.

**(3) The 2026-09-09 reference anchor for `T48n2004` does not reproduce.** Re-running the
collation with the historical comparison the overlay itself records:

```
❌ congronglu: 'drift' claim rests on T48n2004, which is 'drift' against sessions/COLLATION_W1_2026-09-09_refs_manifest.txt;
   a collated-to-witness claim requires byte-verified references
```

(the same run flags the pre-existing `dahui_hongzhi` / `T48n2001` drift). Under §2's reading this
is a pre-pinned-rule artifact of the 2026-09-09 pass, and it has to be adjudicated — not silently
overwritten, since dated evidence is never re-dated or rewritten in place — before the candidate can
be recorded as `collated_to_claimed_witness` in the authoritative record.

document enter the W1 record. Concretely, one of:

## 8. Honest limits

* **No human editorial sign-off.** The containment record's reintroduction gate item 6 ("obtain
  human editorial spot-check/sign-off before public release") is not satisfied; the candidate's
  locators therefore carry `collated_with_normalization` ("human sign-off pending"), never
  `source_checked_excerpt`.
* **Negative fixtures (gate item 5).** The validator's identical-field guard (a case-specific
  Chinese field repeated across ≥3 cases is an error) and the producer's own contiguity assertions
  cover source duplication and numbering/locator drift inside the candidate; no fixture was added to
  `scripts/test_source_preservation.py` in this PR, because the file it would guard is not in the
  corpus yet.
* **Metadata is project-authored.** English and pinyin case titles are drafts, not witness text;
  `title_zh` is the witness heading verbatim (which is why all 101 metadata fields also classify
  EXACT).
* **Front matter and interlinear 著語 are disclosed gaps**, not represented text (§3).
* **Scope respected.** No Pages work, no `quality.yml` edit, no new dependency, no `style=`, no new
  `setProperty`, no law text, no other `data/corpus/*.json` edit, and no quarantined record read or
  copied.
