## Scope

Baseline audit of the entire `translatechan` / Fake Chan Factory repository,
covering 22 aspects across engineering, product, documentation, operations,
quality, presentation, and risk categories. The audit is content-shape-
preserving: no corpus data was modified, no manifest entries were changed,
no locators were moved, no validators were reconfigured.

The audit's primary deliverable is the scoreboard system itself: a
machine-readable YAML + a human-readable Markdown summary + a rubric
+ a history + an agent-handoff + a manual-workflow-edits file + an
updated PR template + this baseline audit log. The audit also covers
the existing project's structural health for handoff to future
sandboxed sessions.

## Limitations of the audit

- **No Playwright run.** `npm run test:browser` requires Chromium,
  which is not installed in this sandbox. The dependency-free
  smoke test (44+ checks) is the regression gate; Playwright
  is a real-browser layer on top.
- **No browser-side smoke.** The audit did not navigate to the
  live `https://56eli.github.io/translatechan/` site. The local
  smoke test exercises the bundle in a Node stub; the live site
  may have CSP nuances that only show up in a real browser. The
  Playwright suite (when Chromium is available) would cover that.
- **No load test.** The performance aspect is a static-byte-count
  audit, not a real-network measurement. The recommended Tier-3
  split is supported by the static analysis only.
- **User scores unknown.** No explicit user scores have been
  provided. All `user_score` fields are `null`. This is the
  expected state for a baseline audit; future sessions should
  surface any user feedback in the scoreboard.
- **Subjective aspects (UX, presentation, content)** are scored
  by a single AI with `confidence: medium` or `high` based on
  observable evidence (smoke test coverage, ARIA roles, data
  shape, etc.). The user may have a different read; their score
  is welcome.
