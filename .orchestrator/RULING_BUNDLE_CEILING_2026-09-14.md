# RULING 2026-09-14 — Bundle Ceiling Extended to 30MB for Testing Phase

**Date:** 2026-09-14 (owner feedback on PR #75)
**Source:** Owner verbatim via ask_user: "The bundle ceiling isn't helping us i believe. Lets extend it to 30mb for the testing phase if technically feasible."

**Status:** DEFINITIVE for testing phase, technically feasible, must be reflected in internal documentation and gates.

## Verbatim Owner Statement

"The bundle ceiling isn't helping us i believe. Lets extend it to 30mb for the testing phase if technically feasible."

## Interpretation as Law

1. **Bundle ceiling extended from 2MB to 30MB for testing phase.** Previous ceiling 2MB (raw 1,925,366 B ~1.84 MiB, gzipped 586,529 B) was tracked after Phase 3 Pages revamp as functional gate-green, but it is NOT helping human-readable overhaul. It constrains drastic layout changes.

2. **Technically feasible:** Yes — bundle is auto-generated by `scripts/build_data_bundle.py`, `app_data.js` is ~1.7MB, `app.js` + `app.css` + `index.html` add ~0.3MB, total raw ~2MB. Extending ceiling to 30MB allows:
   - Multiple layout variants with distinct CSS/JS (not just token swaps)
   - Drastic changes to all rooms: Reader, Compare/Matrix, Lineage, Cases/Gongan, Terms/Lexicon
   - Different number of tabs allowed (same amount of tabs isn't necessarily intended nor forbidden per owner)
   - Progressive disclosure, modals, drawers, hover cards, accordions, etc. without fear of crossing 2MB
   - Keeping ideal colors of 1 as base while varying structure heavily

3. **Enforcement:**
   - `HANDOFF.md`, `AUDIT.md`, `ROADMAP.md`, `README.md`, `OPERATIONS.md` must note testing phase ceiling 30MB
   - `scripts/validate_data.py` does NOT enforce 2MB as hard gate (only docs truthfulness), so no code change needed to enforce — just documentation
   - `scripts/test_website_ruling.py` must NOT fail on bundle >2MB during testing phase, but must still check <30MB
   - Quality workflow `quality.yml` does NOT check bundle size directly, only `git diff --exit-code -- app_data.js docs data/project_metrics.json` — so extending ceiling is documentation-only, technically feasible
   - After testing phase, owner may re-tighten ceiling — this ruling is for testing phase only

4. **Impact on current work:**
   - PR #75 raw 2,023,631 B = 1.93 MiB (just over decimal 2,000,000) was flagged as honest measurement needing owner awareness. Under 30MB ceiling, it is comfortably inside, no trimming needed.
   - Future drastic layout changes (Compare, Lineage, Cases, Terms) can now be implemented without bundle anxiety
   - Allows agents to implement distinct structures per layout, not just colors/fonts
